What PadWake solves differently

Most macOS helpers rely on Bluetooth virtual-HID drivers or only send the USB wake packet. PadWake stays lightweight over USB-C and fixes the second macOS quirk that still leaves games seeing zero controllers.

Fixes the macOS SDL2 veto
Recent macOS versions report GCController support for 057E:2069 without actually publishing a controller, causing embedded-SDL2 games to skip it even after waking. PadWake sets SDL_JOYSTICK_MFI=0 for your session so SDL2 reads the HID stream directly.
No restricted entitlements
No DriverKit extensions, no virtual-HID entitlement approvals, no Homebrew, and no sudo. Compile locally in seconds with Apple's built-in tools or notarize with a standard Developer ID certificate.
Native USB-C HID & paddles
Wakes the hardware's own 21-button, 4-axis HID stream—including rear grip paddles (GL, GR) and C—and installs ready-made gamecontrollerdb.txt and JSON mappings with strictly 1:1 input.

Install or build from source

git clone https://github.com/mindthelatency/padwake.git
cd padwake
make install-app

Builds a Universal Binary, installs /Applications/PadWake.app, and opens it in your menu bar. Enable Launch at Login inside the popover and restart your game launcher once.

Button Support All 21 buttons incl. GL, GR & C
Idle Footprint Event-driven IOKit (~0% CPU)
Distribution Notarized DMG or build locally
